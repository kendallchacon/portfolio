cima-mobile › core/network/NetworkCallAdapter.kt
suspend fun <T> safeApiCall(
    apiCall: suspend () -> Response<T>,
): NetworkResult<T> {
    return try {
        val response = apiCall()
        val body = response.body()

        if (response.isSuccessful && body != null) {
            NetworkResult.Success(body)
        } else when (response.code()) {
            401 -> NetworkResult.Unauthorized()
            409 -> NetworkResult.Conflict(message = parsedMessage)
            else -> NetworkResult.UnknownError(code = response.code())
        }
    } catch (exception: SocketTimeoutException) {
        NetworkResult.NetworkError(
            message = "La solicitud tardó demasiado. Intenta nuevamente.",
        )
    }
}

Cómo decidoHow I decide

Seis criterios que repito en mis proyectos, cada uno con el archivo real donde se ve. Desplaza y el visor cambia.Six principles I repeat across my projects, each with the real file where you can see it. Scroll and the viewer changes.

matchgo-backend

La regla vive donde no se puede saltarThe rule lives where it can't be skipped

Dos personas pueden reservar la misma cancha a la vez. En MatchGo no lo evita un if: lo evita PostgreSQL con una restricción de exclusión sobre el rango de la reserva.Two people can book the same court at once. In MatchGo an if doesn't prevent it: PostgreSQL does, with an exclusion constraint over the booking range.

matchgo-backend

Cada servicio es dueño de sus datosEach service owns its data

Una base de datos por servicio, sin llaves foráneas ni joins entre servicios. Lo que cruza fronteras viaja por APIs o eventos con IDs estables. La decisión quedó escrita en un ADR, con sus costos.One database per service, with no cross-service foreign keys or joins. Anything crossing boundaries travels through APIs or events with stable IDs. The decision is written in an ADR, with its costs.

matchgo-backend

Reintentar sin duplicarRetry without duplicating

Aceptar un reto toca dos bases de datos. En lugar de una transacción distribuida, el ID del reto es la llave de idempotencia de la reserva: si la red falla y se reintenta, no aparece una segunda reserva.Accepting a challenge touches two databases. Instead of a distributed transaction, the challenge ID is the reservation's idempotency key: if the network fails and the request is retried, no second booking appears.

matchgo-mobile

Los errores también son contratoErrors are part of the contract

En las apps que construí, cada respuesta del servidor se convierte en un error tipado. La pantalla sabe si fue validación, conflicto o límite de solicitudes, y un 504 se marca como resultado incierto para no repetir un cobro o una reserva.In the apps I built, every server response becomes a typed error. The screen knows whether it was validation, a conflict or rate limiting, and a 504 is flagged as an uncertain outcome so a payment or booking isn't repeated.

matchgo-mobile

Cada capa con una sola responsabilidadOne responsibility per layer

En Flameware, una revisión de PR me pidió mover lógica del controlador al servicio. Desde entonces lo aplico en todo: en matchgo-mobile cada funcionalidad separa datos, dominio y presentación, y las pantallas nunca llaman a la red.At Flameware, a PR review asked me to move logic from the controller to the service. Since then I apply it everywhere: in matchgo-mobile each feature separates data, domain and presentation, and screens never call the network.

Booking additionally uses PostGIS.

matchgo-mobile › lib/core/network/dio_failure_mapper.dartrepositorio privadoprivate repository
AppFailure _fromResponse(Response<dynamic>? response) {
  final statusCode = response?.statusCode;

  final kind = switch (statusCode) {
    400 || 422 => FailureKind.validation,
    401 => FailureKind.unauthorized,
    409 => FailureKind.conflict,
    429 => FailureKind.rateLimited,
    final int code when code >= 500 => FailureKind.server,
    _ => FailureKind.unknown,
  };

  return AppFailure(
    kind: kind,
    retryAfter: _retryAfter(response),
    // The gateway gave up waiting for the service, which may still finish.
    outcomeUnknown: statusCode == 504,
  );
}

Arquitectura del sistemaSystem architecture

Decisiones del sistema (equipo)System decisions (team)

  1. Una base de datos por servicioOne database per service

    Cada servicio guarda IDs externos, no llaves foráneas cruzadas, y evoluciona su esquema sin coordinar migraciones.Each service stores external IDs, not cross-service foreign keys, and evolves its schema without coordinating migrations.

  2. Eventos con outbox e inboxEvents with outbox and inbox

    El cambio y el evento se guardan en una transacción; si RabbitMQ cae, el evento espera. El consumidor deduplica. El costo es consistencia eventual.The change and the event are stored in one transaction; if RabbitMQ is down, the event waits. The consumer deduplicates. The cost is eventual consistency.

  3. YARP enruta, las APIs autorizanYARP routes, APIs authorize
